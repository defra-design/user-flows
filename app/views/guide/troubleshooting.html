If the page does not load

The user flow is built from the lists at the top of the file, so a small typing mistake can stop the whole page loading.

The error in the terminal where the prototype is running usually gives the line number of the problem. Look at that line and the one before it.

Common mistakes

A missing comma between steps

Wrong

{ "type": "start", "title": "Start page" }
{ "type": "radio", "title": "Who owns the land" }

Right

{ "type": "start", "title": "Start page" },
{ "type": "radio", "title": "Who owns the land" }

A comma after the last step

Wrong

  { "type": "confirmation", "title": "Confirmation page" },
]

Right

  { "type": "confirmation", "title": "Confirmation page" }
]

A missing quote mark

Wrong

{ "type": "map", "title": "Full screen map }

Right

{ "type": "map", "title": "Full screen map" }

A missing bracket in a choice step

Wrong

{ "choice": "Add a boundary", "options": [
  { "type": "draw-polygon", "title": "Draw a polygon" },
  { "type": "upload", "title": "Upload a boundary" }
},

Right

{ "choice": "Add a boundary", "options": [
  { "type": "draw-polygon", "title": "Draw a polygon" },
  { "type": "upload", "title": "Upload a boundary" }
] },

If a screen looks wrong

If a step shows a plain page instead of the wireframe you expected, check the type is spelled exactly as it is in screen types, in lower case.

If a link goes to the wrong page

Check the prototype value matches a file name in the same folder as the user flow, without .html. See linking to prototype pages.
